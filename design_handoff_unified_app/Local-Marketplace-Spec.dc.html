اپلیکیشن بازارچه محلی — سند فنی و محصولی

مارکت‌پلیس چندفروشنده برای پاساژ / مجتمع تجاری — معماری، مدل داده، صفحات و اولویت‌بندی MVP

۱. معماری کلی و ساختار ماژول‌ها

پیشنهاد: Kotlin Multiplatform (Android اولویت، iOS بعداً) + Clean Architecture با ماژول‌بندی feature-first، مشابه اسکلت فنی موجود در ریپازیتوری فعلی تیم (core/*، feature/*) اما با مدل داده‌ی چندفروشنده از پایه.

لایه‌های ماژول
app (composeApp) — ناوبری اصلی، تفکیک گراف مشتری / فروشنده / ادمین
feature-onboarding-vendor — ثبت‌نام فروشگاه، آپلود مدارک، انتخاب حالت کاتالوگ
feature-store — پروفایل فروشگاه، مدیریت فروشگاه توسط Vendor (ساعات کاری، گالری، موقعیت)
feature-product — کاتالوگ محصول با دو حالت Showcase/Commerce، مدیریت محصول Vendor
feature-search — جست‌وجو، فیلتر (طبقه/دسته/قیمت)، نقشه پاساژ
feature-cart-checkout — سبد خرید، سفارش، درگاه پرداخت (فقط برای فروشگاه‌های Commerce Mode)
feature-admin-mall — تایید فروشگاه، مدیریت محتوا، گزارش‌ها (پنل وب یا موبایل جدا)
core/domain, core/data, core/network, core/designSystem, core/navigation — مشترک بین همه فیچرها
  • UI: Jetpack Compose (Multiplatform) — امکان اپ فروشنده و ادمین به‌صورت وب/دسکتاپ با همان Compose برای وب
  • State/DI: MVVM + ViewModel per screen، Koin برای DI
  • Local cache: Room — کاتالوگ، سبد خرید آفلاین، لیست علاقه‌مندی
  • Network: Ktor Client (یا Retrofit روی اندروید) — REST روی بک‌اند Ktor/Spring
  • Auth/Storage/Push: Firebase Auth (OTP موبایل) + Firebase Storage برای گالری تصاویر + FCM برای اعلان تایید فروشگاه/سفارش
  • پرداخت: زرین‌پال یا آیدی‌پی، فقط در مسیر Commerce Mode؛ Showcase Mode اصلاً به درگاه وصل نمی‌شود
  • نقشه داخلی: فاز اول = SVG/Compose Canvas ساده از پلان پاساژ با pin؛ فاز بعد = یکپارچه‌سازی با نقشه واقعی طبقات

۲. مدل داده (Entities)

Entity فیلدهای کلیدی
Userid, phone, name, role (CUSTOMER/VENDOR/ADMIN), avatarUrl, createdAt
Shopid, ownerId (User), name, logoUrl, coverUrl, description, categoryId, floor, unitNumber, mapX, mapY, phone, workingHours[], catalogMode (SHOWCASE/COMMERCE/MIXED), status (PENDING/APPROVED/REJECTED/SUSPENDED), rating, createdAt
Categoryid, name, iconUrl, parentId (nullable, برای زیردسته)
Productid, shopId, name, brand, categoryId, images[], description, mode (SHOWCASE/COMMERCE — می‌تواند مستقل از Shop.catalogMode برای MIXED باشد), price (nullable در Showcase), discountPrice, stock, variants[] (رنگ/سایز), status
Orderid, customerId, shopId, items[] (productId, variant, qty, price), status (PENDING/PROCESSING/SHIPPED/DELIVERED/CANCELED), paymentMethod, totalAmount, addressId, createdAt
Reviewid, productId یا shopId, customerId, rating, comment, createdAt
Floor / MallMapid, floorNumber, label, mapImageUrl, shops[] (با مختصات mapX/mapY)

نکته: Product.mode مستقل از Shop.catalogMode تعریف شده تا حالت «ترکیبی» درخواستی (بخشی کاتالوگ، بخشی قابل‌خرید) در سطح هر محصول پیاده شود، نه فقط سطح فروشگاه.

۳. لیست صفحات و فلوی ناوبری

مشترک / احراز هویت: ورود با OTP → انتخاب نقش (اولین بار) → Splash/Onboarding
خریدار (Customer): خانه (پیشنهادها + دسته‌های محبوب) → جست‌وجو/فیلتر → نتایج (لیست یا نقشه طبقات) → پروفایل فروشگاه → جزئیات محصول (Showcase: تماس/مسیریابی | Commerce: افزودن به سبد) → سبد خرید → پرداخت → پیگیری سفارش → پروفایل کاربر/علاقه‌مندی‌ها
فروشنده (Vendor): ثبت‌نام فروشگاه (فرم چندمرحله‌ای + انتخاب حالت کاتالوگ) → صفحه «در انتظار تایید» → داشبورد فروشگاه → مدیریت محصولات (افزودن/ویرایش، سوییچ Showcase/Commerce به ازای هر محصول) → مدیریت سفارش‌های ورودی (فقط Commerce) → ویرایش پروفایل فروشگاه
ادمین پاساژ (Admin): صف تاییدِ فروشگاه‌های جدید → بررسی مدارک/پروفایل → تایید/رد → مدیریت دسته‌بندی‌ها و نقشه طبقات → گزارش تخلف/گزارش عملکرد فروشگاه‌ها

۴. اولویت‌بندی MVP در مقابل نسخه‌های بعدی

MVP (فاز ۱)
  • ثبت‌نام و پروفایل فروشگاه (اطلاعات پایه، بدون تایید پیچیده — تایید دستی ساده)
  • کاتالوگ Showcase Mode کامل (بدون قیمت/خرید)
  • جست‌وجو و فیلتر پایه (دسته، طبقه)
  • لیست طبقات پاساژ (بدون نقشه تصویری تعاملی)
  • دکمه تماس / نمایش آدرس روی نقشه بیرونی (مثلاً نشان دادن روی نقشه بیرونی گوگل)
  • پنل ادمین حداقلی: تایید/رد فروشگاه
نسخه‌های بعدی
  • Commerce Mode کامل: سبد خرید، درگاه پرداخت، پیگیری سفارش
  • حالت ترکیبی (Mixed) در سطح محصول
  • نقشه تصویری تعاملی داخل پاساژ با مسیریابی pin به pin
  • داشبورد آماری فروشنده و ادمین (فروش، بازدید، پرطرفدارترین)
  • اعلان push برای تخفیف/محصول جدید فروشگاه‌های دنبال‌شده
  • چت پشتیبانی / تیکتینگ بین خریدار و فروشنده

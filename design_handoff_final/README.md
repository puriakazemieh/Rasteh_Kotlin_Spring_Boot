# هندآف کامل: اپلیکیشن بازارچهٔ محلی

> **Complete developer handoff** for the **Local Marketplace** mobile app (customer + vendor + admin).
> این بستهٔ نهایی و کامل است. توسعه‌دهنده‌ای که در گفتگوی طراحی حضور نداشته باید بتواند فقط از روی همین README کل اپ را پیاده‌سازی کند.
> زبان رابط: **فارسی، راست‌به‌چپ (RTL)**.

---

## 0) این بسته چیست و چطور شروع کنم؟ (Quick start برای Claude Code)

**خلاصهٔ کار:** فایل‌های این بسته **مرجع طراحی‌اند که با HTML ساخته شده‌اند** — پروتوتایپ‌هایی که ظاهر و رفتار مورد نظر را نشان می‌دهند، **نه کد تولیدیِ قابل‌کپی**. وظیفهٔ شما این است که این طرح‌ها را در یک کدبیس واقعی **بازسازی** کنید.

**اگر کدبیسی از قبل وجود دارد:** با الگوها، کامپوننت‌ها و کتابخانه‌های همان کدبیس بسازید. Design Tokenهای این سند را با توکن‌های موجود پروژه نگاشت کنید.

**اگر پروژه از صفر شروع می‌شود (پیشنهاد استک):**
- موبایل چندسکویی: **React Native + Expo** یا **Flutter**.
- وب موبایل/PWA: **React + Vite + TypeScript** با **Tailwind** یا CSS-Modules.
- RTL: کل اپ `dir="rtl"`؛ در React Native از `I18nManager.forceRTL(true)`.
- فونت فارسی: **Vazirmatn** (وزن‌های 400/600/700/800).
- state: برای این حجم، Context/Zustand کافی است؛ نیازی به Redux نیست.

**ترتیب پیشنهادی پیاده‌سازی:**
1. توکن‌ها و تم (رنگ، تایپوگرافی، فاصله، شعاع) → بخش Design Tokens.
2. لایهٔ داده و مدل‌ها → بخش Data Model.
3. جریان **مشتری** (مهم‌ترین بخش) → صفحات ۱ تا ۵.
4. جریان **فروشنده** و **ادمین**.
5. تعاملات، انیمیشن‌ها، و حالت‌های خالی/لودینگ/خطا.

**نحوهٔ باز کردن پیش‌نمایش:** فایل `Unified App.dc.html` را در مرورگر باز کنید. نوار تب‌های بالای پیش‌نمایش صرفاً ابزار جابه‌جایی بین نقش‌ها/صفحات است و **بخشی از UI محصول نیست**. فایل‌ها با یک رانتایم داخلی سبک (`support.js`) رندر می‌شوند که **نباید** به پروژهٔ نهایی منتقل شود.

## 1) Overview
یک اپلیکیشن موبایل «بازارچهٔ محلی» که خریداران را به فروشگاه‌های فیزیکی داخل پاساژها/راسته‌های یک شهر متصل می‌کند. کاربر بر اساس **راسته** (دسته‌بندی صنفی مثل مبل، موبایل، طلا) و **محل** (پاساژ/بازار مشخص مثل یافت‌آباد) جست‌وجو می‌کند، فروشگاه‌ها و محصولات را می‌بیند، و با فروشگاه پیام/تماس می‌گیرد.

سه نقش:
- **مشتری (customer)** — تمرکز اصلی؛ جست‌وجو، مرور، سبد خرید، پیام.
- **فروشنده (vendor)** — پنل مدیریت فروشگاه، محصولات، سفارش‌ها، پیام‌ها.
- **ادمین / super-admin** — پنل نظارت، تأیید فروشگاه‌ها، مدیریت راسته‌ها و محل‌ها.

---

## 2) Fidelity
**High-fidelity (hifi).** رنگ‌ها، تایپوگرافی، فاصله‌ها و تعاملات نهایی‌اند؛ UI را پیکسل‌به‌پیکسل بازسازی کنید.

**رنگ‌ها با `oklch()` تعریف شده‌اند.** اگر کدبیس با HEX/RGB کار می‌کند، تبدیل کنید. مقادیر معادل تقریبی رنگ برند: `oklch(0.5 0.19 300)` ≈ `#8b2fd6` (بنفش). برای بقیهٔ رنگ‌ها از یک مبدل oklch→hex استفاده کنید یا مقادیر oklch را مستقیماً در CSS مدرن نگه دارید.

---

## 3) جهت، زبان و اعداد (RTL)
- کل اپ **راست‌به‌چپ (`dir="rtl"`)**. آیکون بازگشت به سمت **راست** اشاره می‌کند (`M9.5 6 15.5 12l-6 6`).
- همهٔ اعداد نمایش‌داده‌شده **فارسی**‌اند (۰۱۲۳۴۵۶۷۸۹)، جداکنندهٔ هزارگان `٬`. تابع کمکی `faDigits()` اعداد لاتین را تبدیل می‌کند — معادل آن را در کدبیس پیاده کنید.
- فونت: `Vazirmatn`، وزن‌های 400 / 600 / 700 / 800.

---

## 4) قاب دستگاه (Device Frame)
صفحات درون یک قاب موبایل عرض **۳۷۵px** رندر می‌شوند. در محصول واقعی این قاب وجود ندارد؛ صفحات تمام‌عرض دستگاه‌اند. نسبت‌ها را حفظ کنید.
- پس‌زمینهٔ صفحه: سفید `oklch(1 0 0)`.
- نوار پایین (bottom tab bar) در بیشتر صفحات مشتری: ارتفاع ~۶۴px؛ padding-bottom محتوا ~۹۰px برای جلوگیری از هم‌پوشانی.

## 5) Screens / Views — جریان مشتری

### ۱) صفحهٔ اصلی — Home / `feed`
**Purpose:** نقطهٔ شروع؛ جست‌وجو، ورود به راسته‌ها، مرور سریع فروشگاه‌ها/محصولات.

**Layout (ستون عمودی، از بالا):**
1. **سرچ‌بار** (بالاترین عنصر — هیچ سربرگ/پروفایل/لوکیشنی بالای آن نیست): ارتفاع ۴۲px، `border-radius:11px`، پس‌زمینه `oklch(0.96 0.01 300)`، padding افقی ۱۳px، آیکون ذره‌بین ۱۷px + placeholder «جست‌وجوی فروشگاه یا محصول…» رنگ `oklch(0.55 0.02 280)` فونت ۱۲.۵px. کلیک → `search`. داخل ناحیهٔ padding `14px 16px 10px` با `border-bottom:1px solid oklch(0.91 0.01 300)`.
2. **گرید راسته‌ها:** عنوان ۱۳px وزن ۸۰۰ `oklch(0.26 0.03 285)`. گرید `repeat(5,1fr)`، `gap:8px 4px`، ۱۰ آیتم = ۲ ردیف. هر آیتم ستون عمودی وسط‌چین `gap:7px`: مربع آیکون ۵۲×۵۲px `border-radius:16px` پس‌زمینه `oklch(0.965 0.008 300)` بوردر `1px solid oklch(0.92 0.01 300)` + SVG استروکی ۲۳px با رنگ اختصاصی راسته؛ برچسب ۱۰px وزن ۶۰۰ `oklch(0.42 0.02 280)`. کلیک → **باتم‌شیت انتخاب محل**.
3. **تب‌های سگمنتد فروشگاه‌ها/محصولات:** کانتینر `flex; gap:4px; background:oklch(0.96 0.01 300); border-radius:10px; padding:3px`. تب فعال: سفید + سایه؛ غیرفعال: شفاف. متن ۱۲.۵px وزن ۷۰۰.
4. **اخیراً دیده‌شده:** فروشگاه‌ها = ردیف افقی اسکرول آواتار دایره‌ای (۵۸px)؛ محصولات = کارت افقی ۱۲۰px (عکس/اموجی ۷۸px + عنوان + قیمت بنفش).
5. **نشان‌شده‌ها (Bookmarked):** عنوان + آیکون بوکمارک پر `oklch(0.5 0.19 300)` + لینک «همه ‹» (→ `bookmarks`). فروشگاه‌ها = کارت ۱۶۰px (کاور + نام + «⭐ امتیاز · طبقه»)؛ محصولات = کارت ۱۲۰px. حالت خالی = باکس خط‌چین.
6. **جدیدترین فروشگاه‌ها/محصولات:** فروشگاه‌ها = لیست عمودی کارت؛ محصولات = گرید ۲ ستونه.

> **توجه:** سربرگ بالای صفحه (انتخاب شهر، عنوان، زنگولهٔ اعلان، آواتار) حذف شده است.

### ۲) باتم‌شیت انتخاب محل — `rastehSheetOpen`
overlay تمام‌صفحه با backdrop `oklch(0.15 0.02 280/0.45)`. شیت از پایین: `border-radius:22px 22px 0 0`، سفید، `padding:10px 18px 22px`، `max-height:78%`، سایهٔ بالا `0 -8px 30px oklch(0 0 0/0.2)`. grab handle ۳۸×۴px `oklch(0.88 0.01 300)`. عنوان «راستهٔ {نام}» ۱۴px وزن ۸۰۰؛ زیرعنوان «محل راسته را انتخاب کنید» ۱۱px. ردیف محل: بوردر `1px solid oklch(0.91 0.01 300)` `border-radius:12px` padding ۱۴px + پین مکان + نام + فلش چپ. ردیف آخر «دیدن همهٔ محل‌ها» با پس‌زمینهٔ `oklch(0.97 0.02 300)`. کلیک → `rastehSearch` با `selectedLocation`.

### ۳) جست‌وجوی درون‌محلی — `rastehSearch`
سربرگ چسبان: دکمهٔ بازگشت + نوار جست‌وجوی نمایشیِ غیرفعال «جست‌وجو در {محل}» (۴۰px، `oklch(0.96 0.01 300)`). دو تب فروشگاه‌ها/محصولات (زیرخط‌دار). بدنه: فروشگاه‌ها = برچسب شمارش + لیست کارت (تصویر ۶۰px + نام + تیک verified سبز + «دسته · طبقه» + «⭐ امتیاز (تعداد)» + برچسب نوع)؛ محصولات = برچسب شمارش + گرید ۲ ستونه (تصویر ۸۸px + برچسب نو/کارکرده + عنوان + قیمت بنفش + «زمان · محل»).

### ۴) صفحهٔ فروشگاه — `shopDetail`
1. **کاور** رنگی + دکمه‌های بازگشت/اشتراک (دایرهٔ سفید ۳۰px با سایه).
2. **بلوک هویت** (margin-top منفی): آواتار دایره‌ای ۶۸px بوردر سفید ۳px اموجی ۳۰px + برچسب نوع + نام ۱۶px وزن ۸۰۰ + تیک verified + زیرعنوان «دسته · طبقه» ۱۱.۵px `oklch(0.52 0.02 280)`.
3. **دکمه‌های اقدام** (`gap:8px`, `margin-top:14px`): «پیام به فروشگاه» = اصلی تمام‌عرض `flex:1` گرادیان برند سفید ۱۳px وزن ۷۰۰ آیکون چت `border-radius:11px` padding ۱۲px (→ `chatThread`)؛ «تماس» = ثانویه بوردر `1.5px solid oklch(0.85 0.01 300)`.
4. **نوار تب زیرخط‌دار:** محصولات · حراجی · ویترینو · نظرات · اطلاعات.

> **توجه:** باکس آمار (دنبال‌کننده/رضایت/عملکرد) و دکمهٔ «دنبال کردن» حذف شده‌اند. فروشگاه مفهوم فالو ندارد.

### ۵) صفحهٔ محصول — `listing`
1. گالری تصویر با dots. 2. عنوان + قیمت بنفش ۱۸px وزن ۸۰۰. 3. برای خریدنی: انتخاب مدل (چیپ). 4. کارت «فروشگاه فروشنده» (آواتار + نام + امتیاز + مشاهده فروشگاه). 5. توضیحات. 6. **امتیاز و نظرات**. 7. **دیدن در فروشگاه‌های دیگر** (بعد از نظرات؛ فقط اگر `isBuyable`): لیست فروشنده (آواتار مربع ۴۰px + نام + تیک + «⭐ امتیاز · طبقه» + قیمت)، ارزان‌ترین با بوردر سبز `2px solid oklch(0.6 0.13 150)` + برچسب «ارزان‌ترین»؛ لینک «مقایسهٔ همهٔ فروشندگان ‹» → `compare`. 8. «گزارش تخلف». 9. **نوار پایین چسبان:** خریدنی = «افزودن به سبد» + «پیشنهاد قیمت» + چت؛ فقط‌حضوری (`isVisitOnly`) = «چت با فروشگاه» + تماس.

## 6) Screens / Views — فروشنده (Vendor)
پنل مدیریت فروشگاه با ناوبری تب پایین: **داشبورد، محصولات، سفارش‌ها/پیام‌ها، پروفایل فروشگاه**.
- **داشبورد:** خلاصهٔ بازدید/پیام/سفارش، دسترسی سریع افزودن محصول.
- **مدیریت محصولات:** لیست محصولات با ویرایش/حذف/فعال‌سازی؛ فرم افزودن محصول (عنوان، قیمت، وضعیت نو/کارکرده، مدل‌ها، عکس‌ها، توضیح).
- **پیام‌ها/سفارش‌ها:** لیست گفتگوها با مشتریان و مدیریت پیشنهاد قیمت.
- **پروفایل فروشگاه:** ویرایش نام، دسته، طبقه، ساعات کاری، آدرس، تلفن، کاور و آواتار.
> جزئیات دقیق layout هر صفحه در `Unified App.dc.html` (نقش vendor) و `Hi-Fi Vendor App (Mobile).dc.html` است.

## 7) Screens / Views — ادمین (Admin / Super-admin)
پنل نظارت:
- **تأیید فروشگاه‌ها:** صف درخواست‌های verify با تأیید/رد.
- **مدیریت راسته‌ها و محل‌ها:** افزودن/ویرایش راسته و نگاشت محل‌ها.
- **گزارش‌ها/تخلفات:** رسیدگی به «گزارش تخلف»های ثبت‌شده.
- **آمار کلی پلتفرم.**
> جزئیات در `Unified App.dc.html` (نقش admin/superadmin) و `Hi-Fi Admin App (Mobile).dc.html`.

## 8) Interactions & Behavior
- **ناوبری:** با تغییر `state.screen`. مقادیر: `feed`, `search`, `rastehSearch`, `shopDetail`, `listing`, `bookmarks`, `chatThread`, `compare`, `citySelect`, `floorMap` + صفحات vendor/admin.
- **راسته → شیت:** کلیک کاشی → `rastehSheetId` ست می‌شود؛ کلیک backdrop → `null`.
- **انتخاب محل:** `screen='rastehSearch'` + `selectedLocation=<نام>` + بستن شیت.
- **تب‌ها:** `homeTab`∈{shops,products}، `rastehTab`∈{shops,products}، `shopTab`∈{products,sale,showcase,reviews,info}.
- **transition شیت:** slide-up، ۲۵۰–۳۰۰ms، ease-out.
- **press-state:** روی عناصر کلیک‌پذیر `cursor:pointer`؛ موبایل = کاهش جزئی روشنایی.
- **حالت‌های خالی/لودینگ/خطا:** برای هر لیست حالت خالی طراحی کنید (باکس خط‌چین + متن راهنما)؛ لودینگ = اسکلتون؛ خطای شبکه = پیام + دکمهٔ تلاش مجدد.

## 9) State Management
- `screen` — صفحهٔ فعال.
- `homeTab`, `rastehTab`, `shopTab`, `bookmarkTab` — وضعیت تب‌ها.
- `rastehSheetId` — راستهٔ باز در شیت (یا null).
- `selectedLocation` — محل انتخاب‌شده.
- `currentShopId`, `currentProductId` — آیتم صفحات جزئیات.
- `bookmarks` (محصولات) و `shopBookmarks` (فروشگاه‌ها) — نگاشت id→بولین.
- `cart` — نگاشت productId→تعداد.
- `city` — پیش‌فرض «تهران».
- `role` — `customer`/`vendor`/`admin`/`superadmin`.

## 10) Data Model
### راسته‌ها (`rastehData`)
`{ id, label, color(oklch), d(svg path), locations:[] }`:
- مبل → یافت‌آباد، حسن‌آباد، مبل ایران
- موبایل → پاساژ علاءالدین، چارسو، پاساژ آسیا
- پوشاک → بازار بزرگ، پالادیوم، مجتمع کوروش
- طلا → بازار طلای تهران، میدان هفت‌تیر، گلستان
- لوازم خانگی → امین‌حضور، چراغ برق، جمهوری
- کیف و کفش → بازار کفش، پاساژ ملت، مجتمع پروما
- آرایشی → پاساژ الماس، بازار ریحان، کوروش
- کتاب و لوازم → انقلاب، کریم‌خان، فلسطین
- اسباب‌بازی → پاساژ کودک، میدان خراسان، بهار
- همه → مجموعهٔ همهٔ محل‌ها

### فروشگاه (`shopsData`)
`{ id, name, category, floor, rating, reviews, verified, type, emoji, coverStyle, hours, address, phone }`.

### محصول (`listingsData`)
`{ id, title, price, emoji, condition, time, loc, shopId, isBuyable, isVisitOnly, description, models[] }`.

## 11) Design Tokens
### رنگ‌ها (oklch)
- برند (بنفش): `oklch(0.5 0.19 300)` — قیمت، لینک، تأکید؛ گرادیان برند برای دکمهٔ اصلی و آواتار.
- متن اصلی: `oklch(0.24–0.26 0.02–0.03 280–285)`.
- متن ثانویه: `oklch(0.5–0.55 0.02 280)`.
- متن کم‌رنگ: `oklch(0.6 0.01 280)`.
- بوردر روشن: `oklch(0.9–0.92 0.01 300)`.
- پس‌زمینهٔ فیلد/چیپ: `oklch(0.96 0.01 300)`.
- سبز تأیید: `oklch(0.5 0.15 150)` (تیک)، `oklch(0.6 0.13 150)` (ارزان‌ترین).
- قرمز هشدار: `oklch(0.58 0.2 25)`.
- زرد ستاره: `oklch(0.65 0.15 70)`.
- آیکون راسته: مبل `oklch(0.55 0.13 45)`، موبایل `oklch(0.5 0.14 260)`، پوشاک `oklch(0.55 0.15 350)`، طلا `oklch(0.62 0.13 85)`، لوازم خانگی `oklch(0.55 0.12 200)`، کیف/کفش `oklch(0.5 0.13 30)`، آرایشی `oklch(0.58 0.15 350)`، کتاب `oklch(0.55 0.11 150)`، اسباب‌بازی `oklch(0.6 0.14 60)`، همه `oklch(0.5 0.02 280)`.

### شعاع گوشه
فیلد/چیپ 10–11px · کارت 12–14px · باتم‌شیت بالا 22px · آواتار 50%.

### تایپوگرافی (px)
عنوان بخش 13/800 · عنوان صفحه/فروشگاه 14–16/800 · بدنه 11.5–12.5 · ریزنوشت 9.5–10 · قیمت محصول 18/800.

### فاصله‌گذاری
مقیاس: 4/6/8/10/12/14/16/18px · gap ستونی Home ~20px · padding افقی صفحات 16–18px.

### سایه
`0 4px 12px oklch(0 0 0/0.12)` (کارت) · `0 -8px 30px oklch(0 0 0/0.2)` (باتم‌شیت/شناور).

## 12) Assets
- **آیکون‌ها:** همگی SVG استروکیِ درون‌خطی (`stroke-width` ~1.7–1.8، `linecap/linejoin:round`). با **Lucide/Feather** معادل‌سازی کنید.
- **تصاویر:** در پروتوتایپ با **اموجی + پس‌زمینهٔ رنگی** جایگزین شده‌اند؛ در محصول واقعی با تصاویر واقعی جایگزین شوند.
- **فونت:** Vazirmatn (یا فونت فارسی موجود کدبیس).

- `Hi-Fi Customer App.dc.html` — نسخهٔ مستقل جریان مشتری (مرجع کمکی).
- `Hi-Fi Vendor App (Mobile).dc.html` — جریان فروشنده (مرجع کمکی).
- `Hi-Fi Admin App (Mobile).dc.html` — جریان ادمین (مرجع کمکی).
- `Local-Marketplace-Spec.dc.html` — سند مشخصات محصول (زمینه).
- `ایدههای نوآورانه.dc.html` — ایده‌های نوآورانه (زمینه).
- `support.js` / `doc-page.js` — **رانتایم پیش‌نمایش. به پروژهٔ نهایی منتقل نشوند.**

> برای دیدن مقدار دقیق هر عنصر، همان عنصر را در `Unified App.dc.html` جست‌وجو کنید — کد درون‌خطیِ style همان چیزی است که رندر می‌شود.
